| DO-001 | P1 | 发现 | 全局 / Ant Design Modal | 控制台出现 `maskClosable` deprecated 警告。 | 当前不阻断使用，但说明组件 API 与 Ant Design 版本存在不一致，后续升级可能变成兼容问题。 | 搜索所有 Modal 用法，将 `maskClosable` 迁移为 `mask.closable`，并做一次页面冒烟测试。 |
| DO-002 | P1 | 已完成 | 前端启动 / 全局样式 | `index.css` 引用了未安装的 `@heroui/styles`，导致 Vite 编译报错。 | 阻断本地前端启动。 | 已删除无效 import。后续引入 UI 库样式时需要同步依赖和使用场景。 |
| DO-003 | P2 | 发现 | 前端构建 | 生产构建提示主 bundle 超过 500 kB。 | 当前不阻断使用，但首屏加载会变慢，后续功能增加后更明显。 | 按路由拆分页面组件，Evaluate、Settings 等低频页面优先做 lazy loading。 |
| DO-004 | P2 | 发现 | 开发启动体验 | `scripts/start_frontend.py` 对 npm/pnpm 的参数处理不一致，pnpm 下会把多余 `--` 传给 Vite。 | 开发者首次启动容易失败或得到不稳定参数行为。 | 已兼容 npm 和 pnpm。后续可在 README 中补充本地启动排障说明。 |
| DO-005 | P2 | 发现 | 侧边栏导航 | 侧边栏 hover 状态颜色对比度不够，黑色背景上使用深蓝强调色时反馈不明显。 | 用户不容易判断当前鼠标悬停目标，导航可感知性偏弱。 | 调整 hover 背景、文字和图标颜色的明度差，必要时增加左侧指示条或更清晰的 active/hover 分层。 |
| DO-006 | P1 | 发现 | Upload / 知识库上传 | 上传知识库文档时不能批量上传。 | 多文档入库效率低，用户需要重复选择和上传，影响知识库初始化体验。 | 支持多文件选择、批量上传进度、逐文件成功/失败反馈，并明确重复文档的处理结果。 |
| DO-007 | P1 | 发现 | Upload / 最近上传记录 | “最近上传记录”刷新后为空，容易让用户误以为知识库文档丢失；实际只是临时记录过期或未持久化。 | 信息模型容易误导用户，对“上传记录”和“已入库知识库”之间的关系缺少清晰边界。 | 将临时上传记录改名为“本次上传结果”，或改为持久化历史；同时在页面上强化“知识库文档列表”作为真实持久状态。 |
| DO-008 | P2 | 发现 | KnowledgeBase / 文档元信息 | 文档操作人似乎写死为 `zhang`，更像无效占位字段。 | 元信息可信度不足，用户可能误以为系统存在真实账号或审计能力。 | 如果暂时没有用户体系，隐藏操作人字段或显示为“本地用户/系统”；如果要保留审计，应从真实登录态或配置中写入。 |
