# Design Optimization Log

这个目录用于记录 RAGTool 的设计优化工作，包括样式、交互、信息架构、响应式、可访问性和工程实现中发现的问题。

它不是设计规范本身。已有规范和视觉参考仍放在 `web/DESIGN.md`、`web/DESIGN_ENHANCEMENT.md`。这里更像一个可持续维护的工作台：先记录问题，再逐步拆解、验证和完成。

## 使用方式

1. 新发现的问题先写入 `backlog.md`。
2. 每个问题尽量带上页面、现象、影响、建议方向和状态。
3. 优先处理影响核心流程的问题，例如上传、配置、问答和评估。
4. 已完成的问题保留记录，方便后续回看设计决策。

## 状态约定

- `发现`：问题已记录，尚未分析。
- `待设计`：需要明确交互、视觉或信息结构方案。
- `待实现`：方案已清楚，可以进入开发。
- `进行中`：正在修改或验证。
- `已完成`：已合入或已确认解决。
- `暂缓`：暂时不处理，但保留上下文。

## 优先级约定

- `P0`：阻断核心流程或造成明显错误。
- `P1`：影响主要体验，应该优先优化。
- `P2`：体验瑕疵或一致性问题。
- `P3`：低风险 polish 或长期改进。
